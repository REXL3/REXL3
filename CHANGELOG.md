Bit-identity records also accept the reviewed earlier runtime id. This matches the development sealer (REXL3/REXL3-dev#343, #344), so requalified receipts composed there verify in production. - Production verification now accepts gate receipts carried forward to a new engine build. A carried gate's evidence keeps the release lock and run paths of the build it was measured on, which change with every binary, so no carried gate could verify before. It is still bound to the model pack, profile choice, capabilities, topology and context, and to a registry-pinned source approval. A carried gate may also come from a lock that only gained a role the profile choice does not fetch, and quality and context may carry to another choice of the same bundle when that choice's fresh exactness gate proves drafted equals serial and cached equals cold at the full window. PR #102.

- Production verification now accepts a carried qualification gate whose source is a complete, all-pass bundle of an earlier engine build that was never sealed, when the evidence also holds a bit-identity record showing the new build answers that bundle binary's requests with identical outputs, a full-window request included. Before, a carried gate needed a registry-pinned sealed approval of the earlier build. Exactness and prefix-cache checks still always re-run. - A model folder whose runtime was renamed can now hold versions sealed under both ids. `MODEL.json` names the runtime's current id; production verification accepts a tree sealed under the earlier id only through its exact reviewed pair in the runtime-id alias table, for a profile choice that tree seals, and refuses any other mismatch. When the first version under the new id is promoted, `tools/promote_runtime.py` moves `MODEL.json` to the new id (and to a reviewed pack-repo rename) only if nothing else changes and every sealed tree in the folder still matches. This lets GLM-5.3-Flash version 2 (`glm53-flash-sage-2.25`) be promoted beside version 1 (`glm53-flash-2.25bpw-sm121`). PR #138.

- `tools/promote_runtime.py` can now promote a later version of a model that is already on `main`. It used to refuse with `existing LATEST differs` whenever `LATEST` named an earlier version, so no requalified version could be promoted. It now moves `LATEST` forward from `v<M>` to the new `v<N>`, and still refuses a `LATEST` that names a later version, is malformed or is not a regular file. PR #137.

- The template allow-list (`runtimes/templates/APPROVED.json`) now accepts a list of approved digests per template version as well as a single digest. Template `v1` lists both the digest the existing trees were sealed against and the digest the v0.1.1 approvals were sealed against, so promotion, carry-source pinning and verification accept the new approvals without re-sealing the existing trees. ## [v0.1.0] - 2026-11-06

First production release of **REXL3**: an OpenAI-compatible Rust + CUDA 13 (`sm_121`) inference engine (`rexl3-serve` and two-node cluster coordinator `rexl3-cluster`) for NVIDIA GB10 (`aarch64`) hosts, shipping five hash-locked EXL3 runtime bundles qualified at their full context windows (`262,144` or `1,048,576` tokens) with lossless speculative decoding and prefix caching enabled by default.

> SAGE is our own mixed-precision quantization method for EXL3. The method is not published.

### Engine, runtime, and release highlights

- Native Rust + CUDA 13 (`sm_121`) engine (`rexl3-serve` and `rexl3-cluster`) supporting uniform and mixed-bit-rate (`MixedK` K2–K8) EXL3 packs, lossless speculative decoding (`drafted == serial` `24/24`), block-hashed prefix caching (`84/84` exact reuse checks), and chunk-size-invariant prefill (`chunked == whole` across `512`/`256`/`128` chunks up to `60,000` tokens).
- Self-contained `./launch.sh` runtime bundles (`install-deps`, `doctor`, `setup`, `verify`, `start`, `smoke`, `status`, `logs`, `diagnostics`, `stop`) with strict boot-time verification of `release.lock.json`, binary SHA-256, and `model.lock.json` shard hashes.
- Change-scoped release qualification (`T0` carry-forward from freeze commit `799fa750f8eb7d4c45d757d9c44beeb7182b5d51` onto primary release engine `afc9b5dfb69d070a306ffe6696d9b4f96db4ddec`) and per-profile subset approvals (PR #64, PR #68).
- Models: qwen3.8/qwen3.8-27b v3, glm-5.3/glm-5.3-flash v1, nemotron-3.5/nemotron-3.5-super-vl v1, qwen3.8/qwen3.8-flash-next v2, deepseek-v4.1/deepseek-v4.1-flash-1017 v1.
