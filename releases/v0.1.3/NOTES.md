## Highlights

- v0.1.3 is a fix release. Every runtime choice of v0.1.1 and v0.1.2 was qualified again, with a fresh full gate chain, on one engine build: engine 0.1.3, engine commit `0c8bc43c`, release binary `rexl3-serve` sha256 `bd77b147…`. No gate result is carried from an earlier engine.
- It ships the fixes for the tester reports listed under Bug fixes: driver and NCCL updates no longer stop an install, the two-node DeepSeek-V4.1 rank check passes, fresh DeepSeek-V4.1 downloads work again, and launcher stops are clean.
- Ling-3.1-Flash-1019 now thinks by default, so a request that names no thinking setting gets a clean answer.
- The known issues listed below replace the "None" of the v0.1.2 notes.
- Every qualification chain ran on the same published release binary, and each seal is verified again by a second maintainer before publication.

## New features and improvements

- Added an opt-in release manifest key, `"evidence_assets": "dev-release"`, for a release whose qualification evidence archives stay on the development release because the raw run files in them include host details. With the key, `tools/cut_release.py` still downloads every model's evidence archive and verifies it against the sealed approval, and a missing or altered archive still refuses the cut, but the archive is not uploaded and is not part of the expected asset set for `--publish` and `--verify`. The release notes then give each archive's name, sha256 and size from the sealed approval and state that it is not a release asset. No approval, registry anchor or promoted tree changes, and a manifest without the key behaves exactly as before, so `v0.1.0` to `v0.1.2` verify as published. See docs/RELEASING.md, "Evidence archives kept on the development release".

- The engine source tree on `main` now matches the v0.1.3 engine commit `0c8bc43cf37318210544cd54da80b5b0bb6ccd76` (tree `5776f1387f040f3c0762c42dc33214512e1194db`). That tree covers `crates/`, `third_party/`, `testdata/`, `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`, `rustfmt.toml`, `.cargo/`, `SOURCE_BUILD.md`, `SOURCE_IDENTITY.json`, `THIRD_PARTY_NOTICES.md`, `tools/switch_registry.json` and the 18 cluster examples under `docs/examples/` that `SOURCE_IDENTITY.json` lists. Every v0.1.3 runtime is sealed on that build. The files are byte-identical to the shared engine-source archive `rexl3-engine-source-0.1.3-0c8bc43c.tar.gz` that the v0.1.3 approvals pin, except that `main` keeps its own `NOTICE` and does not take three files of the export tool.

- **Host packages are checked by known-working versions.** Each runtime's dependency lock states a tested floor and the versions the release was qualified on for `cuda-cudart-13-0`, `libcublas-13-0`, and `libnccl2` in the two-node runtimes.
  - A later version of the same major version is accepted with `DEPENDENCY_NOT_YET_QUALIFIED` instead of being refused, so a routine `apt upgrade` (for example `libnccl2` 2.30.7 to 2.32.6) no longer stops `doctor`, `install-deps` or the two-node launcher.
  - The CUDA runtime, driver CUDA version and cuBLAS reported by `rexl3-serve --version` are judged the same way (`NATIVE_NOT_YET_QUALIFIED`); the binary's own build identity stays exact.
  - A package on `apt-mark hold` reads as installed.
  - Two-node profiles still refuse nodes whose versions differ from each other.
  - Still refused, with what to do in the message: a version below its tested floor, another major version, an NCCL build for another CUDA major version, and an Ubuntu release other than 24.04.
  - `doctor` reports `host_policy`, `dependency_qualification` and `host_versions`.
- **A pending restart is a warning (`REBOOT_PENDING`), not a stop.** A driver upgraded without a restart is refused by name (`DRIVER_MODULE_MISMATCH`).
- **Reproducible engine build.** `cargo build --release --locked` of one commit gives byte-identical `rexl3-serve`, `rexl3-cluster`, `rexl3-router`, `exl3-inspect` and `rexl3-quant` in any directory, for any user, from an empty or a used target directory, when the Rust, CUDA and host compiler versions match. The nodes of a cluster may each build their own binaries; `rexl3-cluster check` compares their sha256 as before. `docs/REPRODUCIBLE_BUILDS.md` lists what must match. The v0.1.3 release binary was built independently on more than one host, with identical bytes.
- **Qwen3.8-Flash-Next decode and prefill.** Decode windows of one to four rows stage only the window's rows for the MoE gate/up, which fits two CTAs per SM. Measured on one GB10 with the shipped argv, 512-token greedy answers at 39-, 4,026- and 35,708-token prompts: decode +0.6 to +0.8% with MTP and +2.9 to +4.0% without speculation. Prefill reads the next chunk's n-gram table pages ahead and runs the routed-expert GEMMs as ring-fed launches. Output bits are unchanged.
- **GLM-5.3-Flash DFlash2 draft licence.** The draft role of the GLM-5.3-Flash lock pins `incoai/GLM-5.3-Flash-DFlash2` at its Apache-2.0 revision `6cc6c481`. The files are the same as the earlier revision, so the locked hashes are unchanged, and the runtime's notices state the Apache-2.0 licence.
- **Prompt log-probabilities on more models.** `/v1/completions` with `prompt_logprobs: k` (0 to 20) runs one teacher-forced pass over the prompt and returns each prompt token's log-probability and the `k` most likely tokens at that position. It was served for DeepSeek-V4.1 only. It is now also served for Qwen3.8-27B, Qwen3.8-Flash-Next, MiniCPM-V-4.7 (text prompts), Ling-3.1-Flash-1019 and Nemotron-3.5-Super-VL, all on one node. Other models refuse it by name, and chat completions do not take it. `docs/REQUEST_CONTRACT.md` in the engine source gives the response shape.
- **DeepSeek-V4.1 `fp16` KV prefill (#110, still open).** The `fp16` index-score kernel is vectorized, with served outputs unchanged. Measured in the review of the change, on a development build and not on the release binary: one GB10, the `dsv41-single-262k` argv and environment with `--kv-dtype fp16` and `--prefix-cache off`, a 33,015-token prompt, median of 3 runs, prompt tokens divided by time to first token. `fp16` prefill was 1,293 tok/s, against 653 tok/s before the change and 1,451 tok/s for `q4` on the same host and build, so part of the gap remains. No shipped profile uses `fp16`, and this release does not qualify it (see Known issues). Reported by @Weschera.
- **DeepSeek-V4.1 image rows (#112, still open).** Image rows now select the vision-language router bias instead of the text-row bias. This does not resolve the report: image input stays off in both DeepSeek-V4.1 profiles (see Known issues). Reported by @Weschera, with a cross-family control from @ExileAI.
- **GLM two-node split `lm-held`, opt-in.** The engine gains a tensor-parallel split in which each rank holds only its vocabulary half of the output head instead of the whole head. No shipped profile turns it on. It is our own implementation, motivated by @justincasey's two-node RED-SNOW-5.3-Flash patch and measurements in #95.
- Discrete GPU memory planning, half-bit EXL3 loading and cache page eviction.
- Ada (sm_89) groundwork: PDL instructions guarded to sm_90 and later, sm_89 EXL3 plans included, and the Ada prefill fallback and capability caches hardened. Ada is not qualified for v0.1.3.
- Flash-Next HCG, HCX and QSA kernels use L2 tiling and shared KV.
- Owned-MoE collectives compacted, and NCCL scatter-gather used.
- DFlash2 absorb uploads are ordered on model streams.

## Bug fixes

- Fixed the release-cut verification to fetch a newly uploaded draft by its release ID before publication, avoiding GitHub's 404 response for draft lookups by tag. This keeps the maintainer release ceremony from stopping after assets have uploaded successfully. Validated against a simulated API; no live release was created or modified. (PR #171)

- Fixed the promotion verifier refusing an approval whose qualification receipt keeps a superseded attempt. When the qualifier reruns a row because its probe changed, it keeps the earlier attempt and its files in the sealed evidence. The verifier now checks that history (each attempt's bytes, the archive, and that a rerun uses a different probe and passes) and expects those files in the evidence asset, as the sealer does. Receipts without a superseded attempt verify as before. (PR #190)

- **Install on an up-to-date DGX Spark (#109).** Runtimes no longer pin one NVIDIA driver package that Ubuntu has since withdrawn. Any 580-branch build from 580.142 is accepted. Builds after 580.178.04, the highest this release was qualified on, print `DRIVER_NOT_YET_QUALIFIED` and continue. The installer keeps an accepted driver, and when the package it would propose is gone it stops by name (`DRIVER_PACKAGE_UNAVAILABLE`) instead of failing inside `apt-get`. Reported by @Weschera and confirmed by @ExileAI.
- **Two-node DeepSeek-V4.1 refused every rank (#109).** Attested two-node `verify`, `prepare` and `start` read each rank's `rexl3-serve --version` without the profile environment, as the sealed identity does. `dsv41-tp2-1m` sets `REXL3_DSV41_KV=q4`, which changed the reported fingerprint, so every rank failed with `NATIVE_VERSION_MISMATCH`. Reported by @Weschera.
- **Fresh DeepSeek-V4.1 downloads (#128).** Both DeepSeek-V4.1 runtimes pin pack revision `c40cf25cc3148bae95ac27483505c883840bf8a7` in place of `cba79c67`, which no longer exists on Hugging Face. All 24 locked files have the same sizes and SHA-256 at both revisions. Reported by @Blackwellboy.
- **The launcher stop cut active streams (#155).** The single-node launcher waits 12 seconds after SIGTERM before it escalates, which covers the engine's graceful stop and its watchdog. If escalation is needed, `stop` reports `STOPPED_FORCED`, exits 24 and records `forced_stop: true` instead of claiming a clean stop. Reported by @NeoAiLabs.
- **Engine build tracking (#156).** CUDA objects are rebuilt when `REXL3_CUDA_ARCH`, the nvcc flags or the CUDA toolkit change, and an interrupted switch can no longer leave a valid-looking build stamp beside stale objects. The vendored tokenizer objects are rebuilt when one of their headers or sources changes. Reported and tested by @Blackwellboy.
- **Malformed model configs (#157)** are refused with a clear error instead of a panic or silent acceptance. Reported by @Blackwellboy.
- **Engine and cluster edge cases (#158):** the TP balancer honours its sweep budget, GLM's MTP debug tail is bounded, truncated `.npy` headers are refused without a panic, and an SSH timeout keeps its output. The `cut_release` part shipped earlier. Reported by @Blackwellboy.
- **RoCE transport (#159):** a failed `start()` leaves the transport retryable instead of marking it started. Reported by @Blackwellboy.
- **Steering overlay loader (#161).** A direction whose width differs from the model's hidden width is refused, naming both widths; the old check compared the length with itself. A cut or malformed overlay file is refused with an error that names the file, instead of a panic. The overlay inflater's fixed-Huffman distance code 0 is corrected. `--intervention` itself is now refused at startup, because no forward pass in this build applies an overlay (see the upgrade notes). No shipped profile passes the flag. Reported by @Blackwellboy.
- **Ling-3.1-Flash-1019 prefill state (#176).** The fused KDA prefill kernel flipped a slot's state parity while other blocks of the same launch could still read it. Now and then one head of one layer was left with another state, and the reply after that prefill could differ between two runs of the same request. The parity now flips only after every block has read it. A run that did not hit the race gives the same bits as before. Found in our own testing; @Blackwellboy reported the same race from the v0.1.1 source.
- **DeepSeek-V4.1 KV documentation (#111):** this model implements `q4` and `fp16` caches only. `--kv-dtype int8` is not a third format: it runs the `q4` cache without an error, which is why `int8` and `q4` measured the same. Reported by @Weschera.
- **DeepSeek-V4.1 decode MoE top-p documentation (#160):** the engine's comment now states the real default, 1.0 (no pruning), and the 16-row cutoff. Nothing changes at run time: both profiles set 1.0. Reported by @Blackwellboy.
- **Qwen3.8-Flash-Next graph caches (#141):** the window and draft-chain CUDA-graph caches are bounded (least recently used, 128 window graphs and 64 chain graphs). An evicted shape is captured again to the same bits, so long sessions with many shapes no longer grow device memory. Reported by @justincasey, whose patch and measurements were the reference for this fix; the patch itself is not part of this release.
- **Ling-3.1-Flash-1019 prefix snapshots** are written to disk with direct I/O instead of through the page cache, to keep snapshot writes from pushing the serving process's memory into swap.
- **DeepSeek-V4.1 tool calls under `stop`:** a reply that ends at a DSML tool-calls block keeps its last text when the request carries a `stop` list.
- **Chat completions accept `parallel_tool_calls`.** Some client libraries add the field on their own; it was refused with HTTP 400. `true`, null or absent serve the reply as before, and `false` ends the reply at its first complete tool call.

## Breaking changes and upgrade notes

- **Ling-3.1-Flash-1019 thinks by default.** `ling31-single-262k` passes `--default-reasoning-effort on`. A request that names neither `chat_template_kwargs.enable_thinking` nor `reasoning_effort` is served as if it sent `enable_thinking: true`: the reasoning comes back in `reasoning_content` and the answer is clean. Reasoning tokens count against `max_tokens`, so a client that relied on the old default with a small `max_tokens` should raise it or turn thinking off. `GET /v1/models` shows the default under `reasoning.default`.
- **The Ling-3.1-Flash-1019 262,144-token boot plans from exact free memory with a 1.5 GiB floor.** It was 2 GiB, from a figure rounded down to a whole GiB. The full window needs about 114.7 GiB of `MemAvailable` when the plan reads it, so start on an idle host with about 115.9 GiB free. A boot below that is still refused by name, and the engine never starts at a smaller window.
- **`./launch.sh stop` can exit 24 (`STOPPED_FORCED`).** Scripts that treated any non-zero exit of `stop` as a failure to stop should accept it: the server has stopped, but not gracefully.
- **`rexl3-serve --intervention DIR` is refused at startup.** No forward pass in this build applies a steering overlay, so the flag used to load an overlay that changed nothing. Remove the flag. No shipped profile passes it (#161).
- **Driver and package warnings.** `DRIVER_NOT_YET_QUALIFIED`, `DEPENDENCY_NOT_YET_QUALIFIED`, `NATIVE_NOT_YET_QUALIFIED` and `REBOOT_PENDING` are warnings, and the command continues. Results on a version newer than the qualified ones are not covered by this release's qualification evidence.
- Each runtime moves to a new version, and `LATEST` moves with it. The earlier versions stay in the tree and keep verifying.

## Known issues

Each runtime's `KNOWN_ISSUES.md` gives the full list, with what happens, who is affected and what to do. In summary:

- **Every runtime: NVIDIA driver.** The 580 branch at build 580.142 or later. Builds after 580.178.04 are accepted with `DRIVER_NOT_YET_QUALIFIED` but are not covered by this release's qualification evidence. Both driver packages must be the same build, on every node of a two-node profile. Another branch (570, 590), or a build below 580.142, is refused. If `install-deps` stops with `DRIVER_PACKAGE_UNAVAILABLE`, install any 580 build at or above 580.142 with the host package manager, reboot, and rerun `./launch.sh doctor`.
- **Two-node runtimes: NCCL.** `libnccl2` 2.30.7 or later on major version 2, the same version on both nodes. Upgrade both together, or hold the package on both.
- **Two-node runtimes: the HTTP endpoint is on the network and has no authentication.** The leader listens on its site-file address, and anyone who can reach the port can use it. Run it on a private network, or behind a firewall or an SSH tunnel.
- **Images are refused** under temporary exceptions:
  - DeepSeek-V4.1-Flash-1017 single-node and two-node, until 2026-12-31: the quantized pack answers a solid-colour probe wrongly. With image input turned on off-profile, a check made after this release's router-bias change still got a wrong answer to an image prompt (#112, open); keep `--no-vision`.
  - Qwen3.8-Flash-Next, until 2027-01-31: the engine does not build its vision tower.
  - Ling-3.1-Flash-1019 is a text-only model.
  - CYBER-FROST-3.8 runs `--no-vision`.
- **Thinking off:**
  - GLM-5.3-Flash (single-node and two-node) always thinks; `enable_thinking: false` has no effect, and the response says so in the `X-Rexl3-Note` header. Lower it with `chat_template_kwargs: {"reasoning_effort": "low"}`.
  - Ling-3.1-Flash-1019 with thinking turned off puts reasoning text and a stray `</think>` into the answer. The default (thinking on) is not affected; this exception expires on 2026-12-31.
- **No thinking unless asked:** MiniCPM-V-4.7, Nemotron-3.5-Super-VL and Qwen3.8-Flash-Next do not think on a request that names no thinking setting, although their chat templates would. Send `chat_template_kwargs` to turn it on; each runtime's file gives the exact field.
- **Qwen3.8-Flash-Next, default choice:** after a prefix-cache hit that ends inside a 256-token page, MTP can accept fewer drafted tokens, so decoding can be slower. Replies are not affected. Continuing an earlier chat turn is such a hit, and the size of the slowdown is not measured. Send `{"prefix_cache": false}` to avoid it for one request (#177, open).
- **GLM-5.3-Flash single-node:** the prefix cache holds one long conversation at a time; a different full-window prompt evicts it.
- **Ling-3.1-Flash-1019 refuses to start at 262,144 tokens on a host short of free memory.** Start on an idle host (see the upgrade notes).
- **DeepSeek-V4.1:** at temperature 0 the model can repeat a phrase until `max_tokens`; keep the sampling defaults for long reasoning. `--kv-dtype int8` silently runs the `q4` cache. `--kv-dtype fp16` is not qualified and its prefill is still slower than `q4` (#110, open; figures under New features and improvements); keep the profile's `q4`.
- **CYBER-FROST-3.8:** greedy decoding (temperature 0) can loop on long generations until `max_tokens`. 6 of the 180 Q200 text replies ran to the 65,536-token budget with no answer. Use the model's sampling defaults: temperature 1.0, top-p 0.95 and top-k 20, from the pack's `generation_config.json`. The opt-in choice `cyberfrost-3.8-dflash-single-262k` is not part of v0.1.3; use the default choice `cyberfrost-3.8-single-262k`. The runtime's own `KNOWN_ISSUES.md` does not list either point yet.
- **Local model copies:** Qwen3.8-27B, MiniCPM-V-4.7 and the Qwen3.8-Flash-Next drafting choice have two packs (target and draft) and cannot use an existing local copy named in a site file; let the launcher download them.
- **Port 8889** is the default of the Qwen3.8-27B, MiniCPM-V-4.7 and Ling-3.1 runtimes. Run one at a time on a host, or set `http_port` in a site file.
- **Nemotron-3.5-Super-VL:** video-frame input is accepted but not part of the release contract (`capabilities.video` is `false`).
- **RED-SNOW-5.3-Flash single-node is not part of v0.1.3.** Its qualification found that the profile's prefix-cache size does not cover the full 262,144-token window. It is planned for a later release with a corrected profile. The two-node RED-SNOW-5.3-Flash profile is not affected.
